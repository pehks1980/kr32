KR32 kernel memory map
=====================

This document describes the current layout defined in kernelshed.asm. Addresses
are hexadecimal. Page sizes are 0x1000 bytes unless otherwise noted.

Kernel image and bootstrap
-------------------------

The kernel entry is at 0x00002000. Kernel code and low-memory globals are
below 0x00010000. The common kernel page table identity-maps
0x00000000-0x0000FFFF, covering those sections. BMI buffers and registers are
in the separate 0x00015000-0x00017FFF range described below.

The bootstrap stack top is 0x0003E000. KERNEL_START must set SP to this value
before executing any instruction that pushes to the stack. This stack is used
only during bootstrap, before the MMU is enabled and a task's kernel stack is
selected. The stack grows downward into the page below 0x0003E000.

Kernel and common mappings
--------------------------

The common kernel mappings are identity mappings:

  0x00000000-0x0000FFFF  Kernel image and low-memory kernel pages
  0x00015000-0x00017FFF  BMI buffers and registers
  0x00100000-0x00101FFF  MMIO
  0x00050000-0x000CFFFF  Physical page allocator pool

The range 0x00010000-0x00014FFF is not included in the common mappings.
Mappings for task-specific user pages are installed in each task's page table.
The allocator pool is mapped for kernel access; its presence in a common
mapping does not make those pages user-accessible.

Per-task stacks and user address space
--------------------------------------

Each task has a separate, dynamically allocated physical page for its kernel
stack. Task creation builds the initial trapframe on that page. When switching
to a task, the kernel loads its saved kernel stack pointer (KSP) and page-table
base register (PTBR) before enabling the MMU. The bootstrap stack at 0x3E000 is
not the per-task kernel stack.

The configured user-address bounds are:

  USER_BASE   0x0003E000
  USER_LIMIT  0x0005FFFF

These bounds are used to reject out-of-range user pointers; they do not mean
that every address in this interval is mapped. Each task's page table must
contain a present, user-accessible mapping for an address to be usable.

Current user virtual addresses:

  0x0003F000  Per-task user stack page; initial user SP is 0x00040000
  0x00040000  Initial task code page (contains TASK_INIT_START at 0x000404FA)
  0x00042000  Per-task user data page
  0x00043000  execve-loaded program code page

The user stack is a separately allocated physical page mapped at 0x3F000.
Addresses such as 0x40000 and 0x42000 are mapped as needed in the task's page
table; the user pointer bounds alone do not guarantee that they are present.

Physical page allocator and built-in archive
--------------------------------------------

The allocator manages 128 pages in the physical range 0x00050000-0x000CFFFF.
It supplies physical pages for task kernel stacks, user stacks, user data, and
other dynamically allocated pages.

The built-in TAR image occupies 0x000A0000-0x000BB5FF, which overlaps the
allocator pool. The current allocator initialization marks only the page at
0x000A0000 as reserved; the other archive pages are not all excluded from
allocation. Do not treat the entire archive range as reserved unless allocator
initialization is updated to reserve it.

Bootstrap sequence
------------------

1. Enter at KERNEL_START and set SP to 0x0003E000 before any push.
2. Initialize kernel state and create task page tables, task kernel stacks,
   initial trapframes, and user mappings.
3. Load the selected task's PTBR and KSP.
4. Enable the MMU and enter the selected task.
